### 2. 【重要】请更新 A 文档第 4.2 节：调用 B 时请支持传入可选第 3 参数 `config`

B 现已支持**直接传普通 `dict`** 作为第 3 参数（无需 A 额外 import `VerificationConfig`，且自动忽略 `case_id`、`notes` 等多余元数据键）：

```python
from src.verification import verify

# 简单组合用例仍兼容 2 参数调用：verify(golden_rtl, candidate_rtl)
# 正式联调（尤其是 case5–case8 时序用例与产物归档）请传 dict 配置：
result = verify(
    golden_rtl="/abs/path/to/case5/rtl.v",
    candidate_rtl="/abs/path/to/runs/case5/iter_001/candidate.v",
    config={
        "top": "verified_accu",
        "mode": "both",                  # "formal" | "simulation" | "both"
        "timeout_seconds": 120,
        "sequential": True,
        "clock": "clk",
        "reset": "rst_n",
        "reset_active_low": True,
        "induction_steps": 5,
        "testbench": "/abs/path/to/case5_tb.v",
        "observed_outputs": ["valid_out", "data_out"],
        "run_dir": "/abs/path/to/runs/case5/iter_001/verify",
    },
)
```

为什么必须传 `config`：
1. **时序用例必需**：`case5`–`case8` 及 4 个隐藏时序用例若不传 `sequential=True`、`clock`、`reset`、`reset_active_low`，Yosys 会按组合电路跑，遇到异步复位 `$adff` 会直接报错；传入后也直接解决了 A 文档第 14 节第 5 条“时序用例复位序列尚未处理”的限制。
2. **产物目录对齐**：显式传 `run_dir="runs/<case>/iter_001/verify"` 才能让 B 的日志和 JSON 落在 A 第 9 节规划的每轮目录内（不传会默认落到 `runs/verification/<timestamp>/`）。
3. **单次超时联动**：B 内部已自带单次超时控制（默认 120s），A 可将 `timeout_seconds` 与整次 `--time-budget` 剩余时间联动，缓解 A 第 14 节第 1 条“单次调用无超时控制”的问题。

8 个公开用例的完整配置已整理在随附的 **`public_cases_manifest.json`**，A 可直接读取某一条目并补充 `run_dir`、`testbench`、`mode` 传给 `verify()`。

## 三、给成员 C（综合与性能评估）

在用 **Yosys 0.71+101** + `NangateOpenCellLibrary_typical.lib` 实测课程 8 个公开用例时，发现以下几项直接影响 `src/evaluation/evaluator.py`（PR #3）的兼容性注意点，建议尽早调整：

1. **多模块用例 `stat -liberty` 面积提取易抓错（重要！）**
   - 实测 `case1`（`barrel_shifter`，同一文件内含子模块 `mux2X1`）时，若在 `stat -liberty` 前未执行 `flatten`，Yosys 输出依次为：
     ```text
     Chip area for module '\mux2X1': 1.862000
     Chip area for module '\barrel_shifter': 0.000000
     Chip area for top module '\barrel_shifter': 44.688000
     ```
   - 当前 PR #3 的 `evaluator.py` 在 `flatten` 之前用 `re.search(r"Chip area for module\s+'.*?':\s*([\d.]+)", ...)`，会误抓到子模块面积 `1.862` 或 `0.0`。
   - **建议**：在 `stat -liberty` 之前先 `flatten`（或优先匹配 `Chip area for top module`）。
2. **`case4`（`div_16bit`）需要 `-sv` 参数**
   - `case4/rtl.v` 使用了 SystemVerilog 语法（`logic`、位宽强转 `16'($unsigned(...))`），`read_verilog` 需要改为 `read_verilog -sv`，否则读入 `case4` 会报语法错。
3. **接口字段与评估口径对齐**
   - 顶层模块字段名：B 和 D 统一使用 `top`，C 当前 PR #3 使用 `top_module`，联调前建议统一为 `top`（或兼容两者）。
   - 确认返回字段与 `docs/interfaces.md` 对齐（补齐 `area_unit`、`delay_unit`、`error_type`、`error_log`），并全组统一 Yosys 版本、工艺库路径和延时口径（`ltp` 拓扑深度 vs 实际延时单位）。
4. **建议移除 `pyosys` 依赖，改用 `subprocess` 调用命令行 `yosys`（强烈建议）**
   - 当前 PR #3 的 `evaluator.py` 依赖 `from pyosys import libyosys as ys`，但实际上仅用 `ys.run_pass(...)` 执行字符串命令并解析 `stat.log`/`ltp.log`，并未用到 `pyosys` 的内存网表遍历能力。
   - 常规 `apt install yosys`、`pip` 和 `oss-cad-suite` 均不自带 `pyosys`，强绑定特定 Python 版本与源码编译（`ENABLE_PYOSYS=1`），队友换 `.venv` 或后续老师/助教复现时极易卡死在 `ModuleNotFoundError: No module named 'pyosys'`。
   - 建议改为与 B 模块及助教 `opti_demo` 一致：拼接 `.ys` 脚本后用标准库 `subprocess.run(["yosys", "-s", ...], timeout=60)` 执行（改动不到 20 行）。这样零额外 Python 依赖、进程隔离更稳（不怕异常 RTL 拖崩主控、也不用依赖线程不安全的 `signal.SIGALRM`），且天然兼容任意 Yosys 版本（0.52 / 0.71）与日志重定向。
