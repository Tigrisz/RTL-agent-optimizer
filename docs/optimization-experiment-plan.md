# D 模块 RTL 优化实验方案 V1

**决策建议。** 保留现有 `optimize(current_rtl, feedback)`。把 D 的核心从按固定顺序尝试策略，升级为根据电路结构提出两个竞争性改写，再用验证和综合反馈决定下一次修改。首版优先攻两种能改变映射后硬件成本的机会：共享宽算术通路，压缩跨流水级传递的数据。每次调用仍只返回一个候选。本方案用于指导 D 模块下一轮开发与实验。

## 一　为什么值得改这两处

现有 D 已能调用模型、管理历史、识别注释与排版重复并保存用量。薄弱环节是策略选择：除不等价和时序不达标外，现有代码按固定顺序轮换四个策略。历史 Demo 的三次真实调用中，两次只得到原样代码或注释变化。这个小样本足以指出一个具体缺陷：给模型“缩小面积”这个方向，它可以在完全不改变电路结构的情况下完成一次回复。[策略实现](https://github.com/Tigrisz/RTL-agent-optimizer/blob/9091378e1a68aa34e1b50a7cdffe6538a13310a9/src/optimization/optimizer.py) · [历史实验](https://github.com/Tigrisz/RTL-agent-optimizer/tree/9091378e1a68aa34e1b50a7cdffe6538a13310a9/experiments/demo_2026-10-17)

Yosys 已经会消除未使用的逻辑、合并相同单元，还能识别部分互斥算子共享。因此，模型仅删除一个死寄存器或把相同表达式提取成一个信号，很可能得到相同网表。D 更值得做的是改变综合器看到的数据通路，并事先说明这种改变可能付出的代价。RTLRewriter 提供了按成本搜索改写方向的参考，SymRTLO 展示了给改写规则增加结构前提的做法。本方案分别采用有预算的候选探索，以及带适用条件的局部改写；论文中的收益数字不作为本项目的预测。[Yosys 优化规则](https://yosyshq.readthedocs.io/projects/yosys/en/stable/using_yosys/synthesis/opt.html) · [RTLRewriter](https://arxiv.org/abs/2409.11414) · [SymRTLO](https://arxiv.org/abs/2504.10369)

## 二　候选怎样产生

1. **提取行为约束。** 读入 A 提供的当前 RTL、顶层和参数。记录输出位宽与有符号性、截断位置、寄存器的时钟和复位、更新使能，以及输出在空拍和停顿时的可观察行为。以原始 RTL 为行为依据。优先复用已有的 elaboration 或网表摘要；没有摘要时，按 RTL 建立局部假设，并标注依据来自源码。
2. **定位值得改变的结构。** 查找互斥分支中的宽算子、比较与减法的重复运算、跨多拍搬运的宽总线、反复译码后控制同组输出的大选择器。若 C 已返回单元类别或路径摘要，用它决定先改哪里。第一版用确定性规则筛选位置，模型负责局部 RTL 改写。
3. **为同一位置准备两个不同假设。** 每条策略记录目标信号、适用前提、预计减少的硬件、可能增加的硬件、必须保持的边界行为。先尝试最有依据的一个；第二个走不同的面积与延时代价路线。避免为获取两份候选重复发送整段历史。
4. **局部改写，返回完整候选。** 每轮只改一处数据通路或一组相关状态。大模块让模型返回带原文锚点的替换片段，D 在本地唯一匹配并重建完整 RTL。锚点失效、结构越界、顶层接口变化或截断时，返回明确错误。小模块沿用现有完整 RTL 输出。候选文件、父版本和提示词都可追溯。
5. **用观测决定下一步。** 文本指纹重复就换结构；B 返回反例就定位第一处错误的位或拍；C 返回面积无收益就检查预期减少的算子是否真的减少。已等价、面积明显下降但未达时序的候选可以作为一次局部修复的素材，其身份标为待修复。正式保留哪个版本仍由 A 决定。

## 三　两项优先实现的结构改写

### 互斥宽算术共享

以仓库里的定点减法器为例。源码同号分支取低位差，异号分支取低位和；异号时的结果符号还取决于幅值比较和截断结果是否为零。两个输入交换顺序相加会得到同一低位结果，但这个观察并不能消除符号逻辑。若直接用标准有符号减法替换整段 RTL，就会改变原始行为。[原始源码](https://github.com/Tigrisz/RTL-agent-optimizer/blob/b59b7db98c450f1353e1de261e96cde676c39aeb/benchmarks/public/opti_cases/case3/rtl.v)

- **面积候选。** 用一个受控加减通路产生低位结果，保留原比较与符号选择。待测假设是省去一条宽算术链的收益大于增加控制异或门和进位选择的代价。
- **时序候选。** 保持和与差并行计算，只合并异号分支中重复的符号与零判定。若面积候选把控制信号推入关键进位路径，这个方向仍有机会得到达标解。
- **必须核对。** 两输入幅值相等、异号、低位加法回绕为零、最高幅值位发生借位，以及非默认合法位宽。收益按映射后面积衡量。若原始综合已完成共享，就将这一策略记为在该结构上无增益。

### 压缩跨流水级传递的数据

仓库里的四级加法器，会把高位段的两个操作数分别寄存多拍，直到前级进位抵达才相加。这里有一个比删自赋值更有价值的机会：后级需要的可能只是“这段局部和以及它怎样响应一个迟到的进位”，而不是两个完整操作数。[原始源码](https://github.com/Tigrisz/RTL-agent-optimizer/blob/b59b7db98c450f1353e1de261e96cde676c39aeb/benchmarks/public/opti_cases/case7/rtl.v)

- **面积候选。** 先只改传递距离最长的一段。在操作数进入时形成扩位局部和，以一个局部和替换两条延迟线，在原加法级加入迟到的进位。对宽度为 w 的一段，每跨一级，数据寄存位数从 2w 降至 w+1。默认 w=16 时，每替换一级理论上少传 15 位。这个数字是结构假设，实际总面积还包括加法逻辑、使能、复位和映射代价。
- **时序候选。** 如果“局部和加一”成为瓶颈，就把该段分为小块，预计算块内和及是否会传播进位，待进位抵达后完成块间校正。试验只改变一个分块选择，便于解释它在延时上换回了多少、在面积上付出了多少。
- **必须核对。** 保持四级有效信号、连续输入吞吐、复位和各级使能。原设计部分寄存器每拍前进，部分仅在对应使能置位时更新；输入有气泡时，仍须逐拍比较所有可观察输出。若不同参数下切片含义不清，缩小改写范围，保留参数化行为。

两条规则由“互斥宽运算”或“两个宽操作数跨多级等待单比特进位”等结构触发。用例名只用于定位示例。一个未见过名称、具有相同结构的模块，应走同一决策路径。

## 四　D 怎样使用反馈

| 收到的证据 | D 的下一步 |
|---|---|
| B 给出语法错误、顶层或端口变化 | 以父版本恢复接口，只重做目标片段，记录生成错误。 |
| B 给出真实不等价及反例 | 将失败候选的精确版本、父版本差异、首个分歧信号及位或周期发给模型。最多修复一次；再次失败，建议换另一结构。 |
| B 返回超时或未证明 | 保存未知状态和证明方式。可提议缩小改写范围；缺少反例时不推断是哪一位算错。 |
| C 显示面积下降、时序违规 | 有路径摘要时只改相关逻辑；仅有整体数值时，试已规划的时序候选并标明依据。 |
| C 显示面积相同、深度相同 | 两个数字相同不代表同一网表。若还有单元分布或路径证据，检查原假设；同一方向重复无收益，切换结构。 |
| 结果缺单位、约束未确认或来自 mock | 可做生成与反馈分支检查，正式结果保留“待测”。C 当前在库映射前调用 `ltp -noff`；D 记录为拓扑深度。若课程接受深度门限，则按深度验收；若要求物理延时，则使用团队确认的静态时序报告。 |

保留现有 `candidate_path`、`strategy`、`is_duplicate` 和用量字段。在 D 自有的 `record.json` 中增记父候选 ID、目标信号、结构改写假设、保留的语义、反馈来源、实测结果和下轮建议。对外仍是一次调用生成一个候选，主控可继续使用原接口。[D 接口](https://github.com/Tigrisz/RTL-agent-optimizer/blob/9091378e1a68aa34e1b50a7cdffe6538a13310a9/docs/optimization.md) · [C 的现有测量顺序](https://github.com/Tigrisz/RTL-agent-optimizer/blob/b59b7db98c450f1353e1de261e96cde676c39aeb/src/evaluation/evaluator.py) · [Yosys 对 ltp 的定义](https://yosyshq.readthedocs.io/projects/yosys/en/0.41/cmd/ltp.html)

### 面积、逻辑深度与可选的 OpenSTA 反馈

C 在 11 月 28 日的 PR 更新中给出了 8 个公开用例的原始基线。当前 C 通过 subprocess 调用 Yosys，返回的 delay 是映射前的最长逻辑深度。比如 case7 的基线为 2470.61 µm²、33 级，来自 C 负责人的本地测量；33 是参考值，只有明确指定的深度上限才是约束。C 当前提交尚无 OpenSTA 调用。[C 负责人更新与基线表](https://github.com/Tigrisz/RTL-agent-optimizer/pull/3#issuecomment-7236547532)

D 保留原有函数签名，扩充 feedback.evaluate 的解释方式与提示词。对当前 C 版本，把 delay 明确标为 logic_depth，单位为级。对同一库、工具和约束配置下的基线与候选，分别向模型给出面积、逻辑深度及各自变化；同时标出约束种类、上限和达标状态。上限缺失时允许比较改善方向，达标状态保留为空。将顶层模块置于候选文件中的其他模块之前，保持当前 C 按首个 module 识别顶层的约定。

若 C 后续提供 OpenSTA 结果，D 再读取可选的物理路径延时、单位、slack、约束以及关键路径起止点，将它们与逻辑深度并列写入反馈。关键路径能对应到 RTL 信号时，提示模型优先修改相应算术链或选择器。若逻辑级数下降而同条件的 STA 仍报告负裕量，则沿 STA 违例路径生成局部修复；只有深度数据时按级数探索。缺失或不可比的数据留空。验收 D 时离线回放三种反馈：只有深度、深度和 STA 齐全、STA 缺失或失败；检查实际提示词和策略选择。

## 五　怎样用一次小实验决定是否值得推广

**问题。** 相同调用预算下，新 D 能否比当前 D 更快地产生等价、满足约束、面积优于原始设计的候选？选择一个含互斥算术的组合电路和一个含长延迟线的时序电路即可完成首轮判别。两者验证机制，未知电路的泛化能力另行报告。

| 实验项 | 建议设置 |
|---|---|
| 基准 | 同一原始 RTL 先取得 B/C 基线。对照组使用固定提交 `9091378` 的 D；实验组使用结构定位、双策略和定点反馈。两组从同一原始版本和空历史开始，接收各自候选的真实反馈。 |
| 预算 | 每组每个设计最多 4 次模型调用，两个设计合计最多 16 次。两组固定模型版本、采样参数、每设计总 token 和墙钟时间上限；总 token 上限在运行前按较长设计的源码与模型输出预估锁定。诊断与修复调用计入预算。 |
| 四次机会 | 实验组第 1 次尝试最强假设，第 2 次探索另一结构或修复一个明确反例，第 3 次针对实测瓶颈局部修改，第 4 次用于最后一次有新证据的尝试。每次调用独立记录，提前达到目标即可结束。 |
| 首要指标 | 对每个设计报告截至第 1、2、3、4 次调用的最佳有效面积降幅，定义为 `(原始面积－候选面积) / 原始面积`。只有等价、时序达标且同配置评估的候选可计入。原始设计达标而候选均无增益时，保留原始面积并记 0%；原始及候选均未达标时标为无可行解。 |
| 成本与质量 | 列出首次可行正收益所需调用数、累计输入和输出 token、端到端耗时、等价通过数/实际送验数、重复候选数/生成数。失败、截断、重复和提前停止均进入成本统计。 |
| 决策 | 若两个设计均有真实、可复现的达标候选，且至少一个在同预算下超过旧 D 的最佳面积降幅，保留该策略进入下一版。若只观察到更早找到相同解，报告效率收益；若两组收益相同，检查综合器已完成的优化；若收益差异很小，使用相同预算做配对复跑并报告波动。 |

**冲刺目标。** 至少一个代表设计实现两位数百分比的映射面积下降并满足已确认的时序约束，另一个设计在面积收益或首次命中成本上优于旧 D。这是用于投入决策的目标。面积、延时、模型成本分别报告，避免用自行指定的加权分数代替课程的排名得分。

## 六　D 的交付与开工顺序

1. **结构识别与策略模板。** 在现有 D 内实现上述两个策略族和局部替换。用重命名信号、改变位宽及不满足触发条件的样例检查策略选择。
2. **反馈与记录。** 扩展 D 自有运行记录，支持准确引用失败候选及反例，区分生成错误、实测退化和未知。用已有反馈记录离线回放，验证每种输入产生的下一步建议；回放结果标明来源。
3. **交给实验使用的材料。** 提供兼容旧调用的 D 模块、带父版本和改写说明的候选文件、配对实验配置、逐轮记录及一页比较表。B/C 真实结果通过现有接口或已落盘的结果文件读取，A 继续负责正式循环与最佳版本。

最有说服力的最终案例应能沿着同一条记录回答四件事：原 RTL 在哪里付出了硬件成本，D 改了什么，等价与时序如何得到确认，相同模型预算下究竟节省了多少面积。
